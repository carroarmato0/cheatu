# cheatu-testbed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `cheatu-testbed` binary (interactive mini dungeon + `--script` protocol) with known memory features, and integration tests that attach `cheatu-core` to it and check results against the true addresses it reports.

**Architecture:** A new std-only workspace crate. `world.rs` owns the game state and its memory layout (statics, a heap chain `WORLD → World → Level → Player → Inventory`); `main.rs` runs either the interactive loop or the script protocol over it. Integration tests in the same crate spawn the binary via `CARGO_BIN_EXE_cheatu-testbed`, attach with `cheatu-core`, and compare.

**Tech Stack:** Rust 2021, std only (binary); `cheatu-core` as dev-dependency.

**Spec:** `docs/superpowers/specs/2026-11-13-testbed-design.md`

## Global Constraints

- Crate `crates/cheatu-testbed`, `publish = false`, binary name `cheatu-testbed`, `version.workspace = true`, `edition.workspace = true`, `license.workspace = true`.
- No runtime dependencies; `cheatu-core = { workspace = true }` only under `[dev-dependencies]`.
- Not packaged: `BINS` in `Makefile` and everything under `packaging/` stay unchanged.
- Game logic has no timers and no randomness; values change only through commands.
- Starting values: gold 100, kills 0, hp 100 (max 100), mana 50.0, xp 0.0, ammo 10.
- Command effects: `fight` hp −7, xp +12.5, kills +1, gold +15 · `heal` mana −10.0, hp +20 capped at max, refused below 10.0 mana · `shoot` ammo −1, refused at 0 · `buy` gold −20, ammo +5, refused below 20 gold · `next` reallocate, mana +25.0.
- hp ≤ 0 after a command → "you died", all values and allocations reset to the start.
- `gold_shown` is set to `gold` after every command.
- Script mode: first line `READY pid=<pid>`; exactly one reply line per input line, starting `OK` or `ERR <reason>`; stdout flushed per line; EOF exits.
- Tests assert behaviour (resolves to the true address), never specific offsets.
- Permission: `LiveSource::open` failing with `PermissionDenied` → test prints `skipped: no permission to attach` and passes, unless `CHEATU_TESTBED_REQUIRE=1`, then it fails.
- macOS cargo: `export PATH="$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin:$PATH"`. Linux runs: podman `rust:1`, `CARGO_TARGET_DIR=/work/target/linux`.
- Every task ends green on: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test -p cheatu-testbed`, on macOS and in the Linux container.
- Never launch cheatu-gui or send keyboard/mouse input: the user may have a full-screen game open.

## Review Focus

1. **Stale copies of the marker** (freed old `Player`, stack temporaries) make `aob("<marker>")` match more than once after `next` or a death → `aob` must stay unique. Pinned by `marker_absent_from_binary` (Task 3) and `aob_marker_survives_restart_and_next` (Task 5).
2. **Script output buffering**: a reply that sits in a buffer hangs the test harness → every reply flushed. Pinned by `replies_are_line_by_line` (Task 3).
3. **Refused actions** (heal at low mana, shoot at 0 ammo, buy at low gold) must not change any value → pinned in Task 2's `refused_actions_change_nothing`.
4. **Child left running** when a test panics → `Testbed` kills the child in `Drop`; pinned by `child_dies_on_drop` (Task 4).
5. **Writing the decoy**: a write to `gold_shown` is undone by the next command while gold stays → pinned by `writing_decoy_has_no_lasting_effect` (Task 4).

### Task 2: Crate and game state (`world.rs`)

**Files:**
- Modify: `Cargo.toml` (workspace `members` += `"crates/cheatu-testbed"`)
- Create: `crates/cheatu-testbed/Cargo.toml`, `crates/cheatu-testbed/src/main.rs` (stub `fn main() {}` plus `mod world;`), `crates/cheatu-testbed/src/world.rs` (with `#[cfg(test)] mod tests`)

**Interfaces:**
- Produces (in `world.rs`, used by Task 3):
  - `pub enum Outcome { Ok, Died, Refused(&'static str) }`
  - `pub enum Action { Fight, Heal, Shoot, Buy, Next }`
  - `pub fn init()` — allocate the starting world, store it in `static WORLD: AtomicPtr<World>`; idempotent-safe to call once at startup.
  - `pub fn apply(a: Action) -> Outcome` — performs the action, handles death, then sets `gold_shown`.
  - `pub struct Values { pub gold: u32, pub kills: u64, pub gold_shown: u32, pub hp: i32, pub mana: f32, pub xp: f64, pub ammo: i16, pub level: u32 }` and `pub fn values() -> Values` (reads from memory each call).
  - `pub fn addrs() -> Vec<(&'static str, u64)>` — in order: `gold, kills, gold_shown, hp, mana, xp, ammo, marker, world` (`world` = address of the `WORLD` static).
  - `pub fn marker() -> [u8; 16]` — reads the marker from the live `Player`.
- Layout (`#[repr(C)]`, this field order):
  - statics: `GOLD: AtomicU32 = AtomicU32::new(100)`, `KILLS: AtomicU64 = AtomicU64::new(0)`, `GOLD_SHOWN: AtomicU32 = AtomicU32::new(100)`, `WORLD: AtomicPtr<World>`.
  - `World { level: Box<Level>, padding: Vec<Box<[u8; 256]>> }` — leaked once, never moves.
  - `Level { number: u32, player: Box<Player> }`
  - `Player { marker: [u8; 16], hp: i32, max_hp: i32, mana: f32, xp: f64, inventory: Box<Inventory> }`
  - `Inventory { head: [u8; 8], ammo: i16, tail: [u8; 6] }` with `head = *b"\xC4\xE7INV\x1D\x9A\x3B"`, `tail = *b"\x5E\xA1\x07\x77\xD2\x0C"`.
- Marker: plaintext `b"CHEATU-TESTBED!!"`, stored in the binary only XOR'd with `0xA5`; decoded byte-by-byte straight into the heap `Player` with `std::ptr::write_volatile` (no stack copy of the whole array). `Drop` for `Player` and `Inventory` zeroes `marker`/`head`/`tail` with `write_volatile` before freeing.
- `next`: allocate the new `Level`/`Player`/`Inventory` *before* dropping the old ones, push 4 fresh padding boxes onto `World.padding` in between, carry values over, `number += 1`, mana +25.0.
- Single-threaded; unsafe is confined to reading through `WORLD` and the volatile writes, each with a `// SAFETY:` comment.

### Task 3: Interactive and script front ends

**Files:**
- Modify: `crates/cheatu-testbed/src/main.rs`
- Create: `crates/cheatu-testbed/src/script.rs`, `crates/cheatu-testbed/tests/protocol.rs`
- Modify: `Makefile` (target `testbed`, `## Build and run the cheatu-testbed target game`: `cargo run --release -p cheatu-testbed`; plus the header comment line under "Development")

**Interfaces:**
- Consumes: Task 2's `init`, `apply`, `values`, `addrs`, `marker`, `Action`, `Outcome`.
- Produces: `cheatu-testbed --script` protocol (Task 4 depends on these exact strings):
  - startup: `READY pid=<decimal pid>`
  - values line `V` = `gold=<u32> kills=<u64> gold_shown=<u32> hp=<i32> mana=<f32 Display> xp=<f64 Display> ammo=<i16> level=<u32>`
  - `status` → `OK <V>`; `fight|heal|shoot|buy|next` → `OK <V>`, or `OK died <V>` on death, or `ERR <reason>` when refused (reasons: `not enough mana`, `no ammo`, `not enough gold`)
  - `addrs` → `OK gold=0x<hex> kills=0x… gold_shown=0x… hp=0x… mana=0x… xp=0x… ammo=0x… marker=0x… world=0x…` (lowercase hex)
  - `get <name>` (name ∈ gold, kills, gold_shown, hp, mana, xp, ammo, level) → `OK <value>`; unknown → `ERR unknown value`
  - `marker` → `OK <32 lowercase hex digits>`
  - `help` → `OK <space-separated command list>`; `quit` → `OK bye` then exit 0; empty line → `ERR empty`; anything else → `ERR unknown command`
- Interactive mode (no args): banner `cheatu-testbed — pid <pid>. Type help.`, prompt `> `, after each command print a one-line status (`Level 1  HP 93/100  Mana 50  XP 12.5  Gold 115  Ammo 10  Kills 1`) or the refusal / `You died! Starting over.`; `addrs` and `marker` also work there; EOF or `quit` exits.
- Unknown CLI argument → usage on stderr, exit 2.
